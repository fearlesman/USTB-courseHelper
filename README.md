# USTB-courseHelper

面向 `byyt.ustb.edu.cn` 的北京科技大学选课辅助图形脚本。当前支持体育课以外的课程查询、课程列表缓存和定时选课。

## 运行环境

- Python 3.12（已使用该版本验证）
- Chrome 浏览器
- Selenium 4.35.0（使用内置 Selenium Manager 自动匹配 ChromeDriver）

安装依赖：

```bash
pip install orjson requests selenium selenium-wire pillow beautifulsoup4 pytest
```

启动程序：

```bash
python USTB-courseHelper.py
```

## ChromeDriver 自动匹配

程序启动后会立即在后台通过 Selenium Manager 识别已安装的 Chrome 主版本，并下载或复用缓存中匹配的 ChromeDriver；界面构建和驱动匹配并行进行。预匹配使用临时无头浏览器，成功写入缓存后立即关闭，不会长期占用浏览器进程。预匹配完成前，登录页和中央扫码区域持续显示“浏览器驱动准备中...”，顶栏登录按钮保持禁用；成功后应用无需再次确认，自动启动登录浏览器并在中央生成二维码，不会并发重复下载驱动。项目不再使用 `drivers/` 中的固定驱动，因此 Chrome 自动更新后不会继续误用旧版本驱动。

首次启动或 Chrome 主版本升级后需要能访问 Chrome for Testing 下载源；匹配成功的驱动会缓存到当前用户的 Selenium 缓存目录，后续登录无需重复下载。若后台预匹配失败，中央扫码区域会保留失败提示并显示“重新生成二维码”；点击后显示包含原始原因的中文错误。请确认 Chrome 已安装，并检查网络、代理或下载源访问情况。

## 学年学期（xnxq）

课程查询页的“学年学期”输入框会在启动时按当天日期自动填充，格式为 `YYYY-YYYY-N`，仍可手动修改。

| 日期范围 | 以 2025 年为例 | 自动值 |
| --- | --- | --- |
| 1 月 1 日至 5 月 31 日 | 2025-01-01 至 2025-05-31 | `2024-2025-2` |
| 6 月 1 日至 7 月 27 日 | 2025-06-01 至 2025-07-27 | `2024-2025-3` |
| 7 月 28 日至 12 月 31 日 | 2025-07-28 至 2025-12-31 | `2025-2026-1` |

## 课程联合查询

课程页面支持“课程代码、课程名称”的联合筛选，至少填写一项。查询请求会同时使用 `p_kcdm_cxrw` 和 `p_gjz`；课程类别仅用于展示，不作为筛选条件。

查询结果会递归剔除 `null`、空文本、空列表和空对象，保留 `0` 与 `false`。结果表字段与接口字段的映射如下：

| 展示列 | 接口字段 |
| --- | --- |
| 展示名称 | `rwmc`，缺失时回退 `kcmc` |
| 课程代码、课程名称 | `kcdm`、`kcmc` |
| 课程性质、课程类别 | `kcxzmc`、`kclbmc` |
| 授课语言、计分方式 | `skyymc`、`jfzlbmc`，缺失时回退 `jfxs` |
| 学分、学时、上课信息 | `xf`、`zxs`、`kcxx` 中的青色标签 |
| 容量/已选、开课学院、校区 | `zrl/yxzrs`、`kkyxmc`、`xiaoqumc` |

课程类型默认选择“所有”，会分别查询素质扩展课、专业扩展课、MOOC 和必修课，并按任务 ID 去重合并结果。查询不会自动加入抢课列表。添加前必须先在“抢课任务”页设置抢课人员，再在结果表中选择课程、设置优先级并点击“添加选中课程”；添加成功后程序会自动返回抢课任务页。请求默认每页仅获取 17 条结果，避免无筛选或宽泛筛选产生过大的响应。

## 抢课模式

“轮询模式”会立即开始轮询。“定时抢课”被选中时才会显示抢课时间输入框；到达指定时间后，定时任务会进入与轮询模式相同的持续轮询流程。若设定时间已到或已过，会立即开始轮询，不会等待到次日。

## 命名抢课列表

抢课任务页支持将当前待抢课程显式保存为带名称和备注的命名列表。命名列表与自动草稿是两套独立数据：

- `user_data/<UUID>/course_list.json` 是当前草稿，课程增删、30 秒自动保存和关闭程序时会更新，继续沿用原有数组格式。
- `user_data/<UUID>/saved_rush_lists.json` 是命名列表库，只在用户点击保存、另存为、编辑、删除或分配时更新，不会被自动保存覆盖。
- 每位用户拥有独立列表库，只能查看和加载自己的列表。旧版按人员名称保存的文件只在首次创建同名档案时复制导入，源文件保留为兼容备份。
- 列表名称去除首尾空白后必须为 1–40 个字符，同一人员下忽略大小写后不可重复；备注允许为空，最多 300 个字符；空课程列表不能保存。
- 保存时会深拷贝课程快照并移除界面序号，加载时重新生成连续序号。加载前必须确认，确认后完整替换当前草稿并立即写入草稿文件；取消或读取失败不会改变屏幕上的课程。
- 命名列表写入使用同目录临时文件与原子替换。文件损坏、字段非法或写入失败时会显示中文诊断，当前待抢任务保持不变。

命名列表文件版本 1 的结构如下：

```json
{
  "version": 1,
  "lists": [
    {
      "id": "UUID",
      "name": "列表名称",
      "note": "列表备注",
      "created_at": "ISO-8601",
      "updated_at": "ISO-8601",
      "courses": []
    }
  ]
}
```

## 界面设计

界面采用“渐进式账号顶栏 + 课程查询 / 抢课任务双页工作区”的浅色工作台布局：

- 顶栏不再始终显示用户下拉框和空闲任务文本。未登录时显示扫码入口，任务非空闲时显示任务状态；账号菜单作为低干扰入口，仅在存在多个账号时显示当前账号名称和切换项。
- 程序启动后先显示精简扫码页；ChromeDriver 准备完成后自动打开登录浏览器并直接生成二维码，不再要求先点击确认登录。已有账号在驱动准备期间可以选择“暂不登录，离线进入”，继续整理草稿和命名列表，但查询和启动抢课不可用。登录成功后直接进入抢课任务页，不弹出成功或多账号说明窗口。
- 登录页仅在存在多个启用账号时显示登录目标选择器。账号管理从顶栏账号菜单打开独立窗口，不再占用整个登录页面。
- 非当前账号有等待、抢课或停止中的任务时，顶栏显示“其他账号正在运行”提示；切换账号或关闭账号管理窗口不会停止后台任务。
- 课程查询页只负责筛选、查询结果和设置加入任务时的优先级。结果表占据页面主体，13 个展示字段均可通过横向滚动查看。
- 抢课任务页始终显示待抢课程表、课程数量和空状态。人员、轮询/定时模式、停止策略与开始/停止操作集中在该页，不再占用页面空间显示实时控制台。
- 抢课任务页顶部显示当前命名列表、备注摘要和未保存状态，并提供“保存列表”和“管理列表”；添加或删除课程后会标记为“有未保存更改”。
- 任务设置压缩为人员、模式、停止策略和满课策略四区；定时时间在第二行按需显示。添加与删除课程位于待抢表工具栏，开始与停止位于表格下方。
- 空任务表提供直接前往课程查询的操作；窗口最小化或恢复不会产生无意义日志。
- “抢课时间”仅在定时模式显示；启动抢课后人员、模式和策略会锁定，任务结束后恢复。
- 抢课运行期间保存、管理、加载、编辑和删除命名列表均被锁定，避免后台任务使用的课程集合在运行中变化。
- 首次无账号时显示与工作区同风格的精简扫码页：页面中央使用固定 `400×430` 扫码主体直接展示约 `300×300` 的清晰二维码，不显示说明栏或中间确认按钮；内部自动创建“默认用户”，无需用户填写名称。二维码过期或登录失败后才显示“重新生成二维码”。
- 默认窗口为 `1280×860`，最小窗口为 `1120×720`；两种尺寸下待抢课程表和操作栏均应保持可见且互不遮挡。

青绿色用于登录、查询和开始抢课，白色描边按钮用于次要操作，红色用于停止抢课。查询结果表与待抢课程表均使用独立的横向、纵向滚动条。

## 文件日志

- 程序启动时自动创建项目根目录下的 `logs/`，所有原控制台输出按 UTF-8 写入 `logs/application-YYYY-MM-DD.log`。
- 日志按日期分文件，同一天重复启动会继续追加而不是覆盖；每行包含本地时间戳，多用户业务日志继续带用户别名前缀。
- 源码方式运行时仍保留终端回显，但 Tkinter 界面不再展示控制台或“清空日志”按钮。
- `logs/` 已加入 `.gitignore`，运行日志不会进入版本控制。

## 多用户会话

程序底层继续隔离多名抢课用户，但默认界面按单账号使用方式呈现：

- 首次打开且尚无账号档案时，独立登录视图只显示扫码入口，不要求用户理解或创建档案。首次扫码时程序在后台创建“默认用户”，成功后直接进入工作区；单账号主流程不会展示该内部别名。
- 仅有一个启用账号时隐藏登录目标选择器，顶栏账号菜单显示为“账号”；添加第二个账号后，登录页才显示目标选择器，账号菜单才显示名称与切换项。
- 已有账号再次启动时先显示扫码页，驱动准备完成后自动打开浏览器并生成中央二维码。用户可以直接扫码，也可以在自动登录尚未开始时选择“暂不登录，离线进入”。
- “添加其他账号”位于顶栏账号菜单。新账号先填写唯一名称，再进入扫码流程；登录失败时恢复添加前的当前账号，新档案保留以便重试。
- 账号管理使用独立窗口，显示账号名称、登录状态、任务状态和最近结果，并提供添加、重命名、切换和登录操作。
- 若旧版本曾因扫码失败留下隐藏的“默认用户”档案，直接扫码会恢复并复用原 UUID 和课程目录，不会再次创建同名用户；扫码失败也不会再停用或隐藏该档案。

- 每名用户有稳定 UUID、唯一别名和创建/更新时间。别名首尾空白会去除，长度为 1–40 个字符，并按 `casefold()` 检查唯一性。旧版本档案中的启用状态字段仍兼容读取，但当前界面不再提供停用或恢复功能。
- 用户数据位于 `user_data/<UUID>/`。草稿保存为 `course_list.json`，命名列表保存为 `saved_rush_lists.json`。首次创建档案时会导入同名旧版 `course_list_<人员>.json` 和 `saved_rush_lists_<人员>.json`，旧文件不会删除或覆盖。
- `UserRuntimeContext` 只在本次进程保存 Cookie、登录状态、任务线程、停止事件、定时设置、查询缓存和日志。Cookie、Token、SESSION 等凭据永不写入用户档案、草稿、命名列表、测试或文档；程序重启后用户均需重新登录。
- `MultiUserRuntime.enabled_contexts()` 与 `active_task_contexts()` 提供只读元组快照，界面不直接遍历内部上下文字典；非当前账号存在活动任务时顶栏按数量提示。
- 同一时刻只允许一个 Selenium 扫码登录流程；登录完成后不同用户可以同时轮询或定时抢课。每个任务使用自己的 `requests.Session`、课程快照和停止事件，停止或会话过期只影响对应用户。
- 扫码流程会识别统一认证页的“二维码已失效”提示，并使用 180 秒作为异常页面的兜底超时。失效后程序立即释放全局扫码锁、关闭临时浏览器并清除旧二维码，当前用户或其他用户可以重新扫码。
- 查询开始时会绑定发起用户 UUID。切换当前用户不会把旧用户的查询结果、课程或日志写入新用户；未登录用户仍可离线编辑草稿和命名列表，但查询和启动抢课会保持禁用。
- 切换到尚未查询过课程的用户时，结果区只显示“当前用户暂无查询结果”，不会弹出“未找到符合条件的课程”；该弹窗只用于一次真实查询返回空结果的场景。
- 抢课任务页的当前列表名称支持行内修改：已加载列表只更新名称元数据并保留备注和课程的未保存状态；未命名且有课程的草稿会创建新列表；空草稿、重复名称或非法名称不会改变当前状态。
- 命名列表管理窗口可以把列表深拷贝分配给多个用户。分配只创建独立命名副本，不替换目标用户草稿；目标用户已有同名列表时跳过且不覆盖，之后各副本互不传播。

切换账号不会停止其他账号任务；关闭程序时会请求停止全部任务并保存各账号草稿。业务日志统一写入 `logs/`，界面不显示实时控制台。
